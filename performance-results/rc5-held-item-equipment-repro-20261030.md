## Source trace and candidate fix

Source trace: the owner backend forwards a valid selected-slot action to peer mirrors. The peer `ExternalPlayer` changes its selected slot, but equipment must be sent from that mirror to local trackers. Candidate code does this explicitly; the valid protocol baseline failed while the current candidate passed.

Candidate source change in `ExternalPlayer.java`: consume equipment packets generated by an external-player mirror and send them to that mirror's local entity-tracking viewers; do not bounce that derived packet back to the owner. This preserves authoritative ownership of inventory and selected-slot state. The existing `PlayerActionPacket` remains the selected-slot source of truth.
