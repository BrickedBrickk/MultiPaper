## Newly documented configuration findings

- `sync-settings.sync-permissions` defaults to `false`. Set it to `true` on every backend if effective permissions should follow player ownership changes; still configure permission plugins/grants consistently. A fresh runtime regression found that data was synchronized but `ExternalPlayer.hasPermission` ignored it. The active persistent patch now adds permission-data fallbacks for both `hasPermission(String)` and `hasPermission(Permission)` in `multipaper-server/paper-patches/files/src/main/java/org/bukkit/craftbukkit/entity/CraftPlayer.java.patch`. Java 25 compilation passed, and a disposable two-backend regression passed grant and revoke: the owning `CraftPlayer` and remote `ExternalPlayer` both reported true/data=true after grant and false/data=false after revoke. Detailed evidence is in `performance-results/permission-sync-external-player-regression-20261024.txt`.
- GrimAC routes violations, sessions, player identities, and settings to SQLite by default. SQLite is local/single-server; shared history requires both backends configured to the same MySQL/PostgreSQL service with its JDBC driver present. This does not affect MultiPaper world/inventory replication. Shared SQL was not tested. Details are in both candidate installation guides and the candidate report.
- GrimAC warns that ViaBackwards on 1.21.2+ has unsupported older-client vehicle behavior. Legitimate-client behavior and the compatibility decision remain open.
