## Proxy authentication and Floodgate source audit — 2026-10-25

- Source review confirms the Master game proxy is a transparent TCP tunnel. `MultiPaper-Master/src/main/java/puregero/multipaper/server/proxy/ProxyServer.java` selects an online registered backend, and `ProxiedConnection.java` rewrites only the initial Minecraft handshake by appending the remote client IP when forwarding data is absent. It does not terminate Minecraft login, perform account authentication, or inspect/alter login plugin messages.
- The persistent Paper handshake patch accepts the two-field `host\0client-ip` forwarding form and sets the remote address without a spoofed UUID. The backend therefore retains responsibility for online-mode session authentication. This is a source-path finding, not a successful real authenticated login test.
- Floodgate standalone depends on Geyser configured with `auth-type: floodgate`, the standalone Geyser key matching backend Floodgate's key, and Floodgate installed on the Java server. The transparent tunnel should carry login/plugin traffic to the selected backend; actual Bedrock identity, reconnect, and ownership transfer remain unverified. Official setup: [Floodgate Setup](https://geysermc.org/wiki/floodgate/setup/) and [Geyser Standalone Setup](https://geysermc.org/wiki/geyser/setup/self/standalone/).
- The disposable exact-hash RC4 runtime smoke loaded Floodgate on both backends but did not exercise real account authentication or Bedrock login. No production/Crafty access occurred.
